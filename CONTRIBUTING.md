# Contributing to PocketMate on GitHub

Thank you for taking the time to contribute to **[PocketMate](https://github.com/kylabuildsthings-oss/pocket_mate)**.

We want you to have a great experience making your first contribution. That might be a small documentation fix, a typo, or a full feature—tell us what you enjoy working on and we will try to help.

If you would like to contribute but don't know where to start, look for issues labeled **`good first issue`** or **`help wanted`**.

You can contribute to documentation and code in **TypeScript**, **Solidity**, and **Rust (Forge)**.

If you have other questions about contributing, please open a discussion thread or issue on the repository.

## Code style

Please follow the [Node.js style guide](https://github.com/felixge/node-style-guide) where it applies to JavaScript/TypeScript in this repo.

## Code of Conduct

We strive to keep the PocketMate community open and welcoming. Please read and follow **[CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md)**.

## Get help

Questions or integration help: open a **[GitHub issue](https://github.com/kylabuildsthings-oss/pocket_mate/issues)** with context, or use the support channel your deployment documents (**`NEXT_PUBLIC_SUPPORT_EMAIL`**, etc.).

## Report a bug

If you find a bug in the source code, please **[submit an issue](https://github.com/kylabuildsthings-oss/pocket_mate/issues)** or, better, a **pull request** with a fix.

Before filing a new issue, **[search existing issues](https://github.com/kylabuildsthings-oss/pocket_mate/issues)** to avoid duplicates.

## Request a new feature

If you have an idea that would help everyone, open an issue describing the problem and proposed approach (or use your team's feature channel if you maintain a private fork).

## Pull requests

Pull request descriptions may start with one of: ⭐ | 🌟 | ✨ | 🤩 (optional fun, not required for all repos—match what maintainers ask for in review).

### Commits

- All authors of commits in a pull request must follow our **[Code of Conduct](./CODE_OF_CONDUCT.md)**.
- We prefer a **linear history**: avoid merge commits in feature branches; **rebase** onto the base branch when updating.

### Commit messages

Each commit message has a header with a **type**, optional **scope**, and **subject**:

```
<type>(<scope>): <subject>
```

- The full first line should stay **≤ 100 characters**.
- **type** (lowercase) is required, for example:
  - **build**: build system or external dependencies
  - **ci**: CI configuration
  - **feat**: new feature (e.g. `feat(typescript): ...`)
  - **fix**: bug fix (e.g. `fix(api): ...`)
  - **refactor**: change that is not a feature or fix
  - **style**: formatting only
  - **test**: tests
  - **docs**: documentation only
  - **chore**: routine maintenance
